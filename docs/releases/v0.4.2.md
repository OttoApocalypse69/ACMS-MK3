ACMS mk3 0.4.2 is a second security release. Everyone on 0.4.1 or earlier should update.

A second audit found more ways for a crafted file or a script to take ACMS down, and one way for a script to step in for another. All of them are fixed.

## Files

- **Aseprite:** a small crafted file could crash ACMS outright, with no chance to save. The data it used is now skipped, since ACMS never needed it. Frames, layers, tags and slices are also limited one by one.
- **CMG, palettes and `.acms` tiles:** checked as they are read, so a file cannot claim millions of rows, colours or tiles and fill the memory first.

## Scripts

- A script can no longer register a command under the id of one of ACMS's own commands. Such a script could otherwise run in place of that command whenever another script called it, using the folder that script had been given.

## Limits while you work

- A sprite has at most 4096 layers, 10 000 frames, 4096 tags and slices, 1024 tilesets, 65 536 tiles a tileset, 256 colours and 256 ramps. These were already the limits for opening files; now edits and scripts keep to them too.
- One change (scaling the sprite, merging, flattening, replacing colours) may use at most 1 GB. Linked and copied frames still share their pictures when the sprite is resized or scaled, so this only stops changes that really are that large.
- GIF, timelapse and spritesheet exports are size-checked before anything is drawn, like PNG exports.
- Moving a layer works even when the sprite has all the layers it can have.

The whole list, finding by finding, is in [PROGRESS.md](https://github.com/OttoApocalypse69/ACMS-MK3/blob/main/PROGRESS.md).
