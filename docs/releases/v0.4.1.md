ACMS mk3 0.4.1 is a security release. Everyone on 0.4.0 or earlier should update.

An outside audit found ways for a script or a crafted file to reach past where it should, or to take the app down. All of them are fixed.

## Scripts

- **Files:** a script can only name files *inside* a folder you picked for it. Links that lead out of the folder are not followed, and the permission ends when the script does.
- **Commands:** scripts may run the commands that work on sprites, but not the ones that reach past them. They can no longer save over a file without a path, use the clipboard, change preferences or shortcuts, run other scripts, recover autosaves, close sprites or quit.
- **Isolation:** each script has its own globals and its own copies of the libraries, so one script cannot change what another sees.
- **Limits that hold:** catching the time-limit error no longer keeps a script running. Pictures, printed text, dialogs, open sprites and pattern matching all have limits, so a script cannot freeze the app or fill the memory.

## Files

- PNG, `.acms`, Aseprite and Netpbm files are checked before memory is set aside for them. A small crafted file can no longer claim a huge picture, nest groups without end, or overflow a number and crash the app.
- Saving writes to a new temporary file each time, so two windows never share one.

## Crash recovery

- Two ACMS windows no longer take each other's autosaves for leftovers of a crash.
- A recovered sprite is only saved back to a `.acms` file, and the recovery dialog shows where.

## Also

- Scripts that used the commands now refused, or matched patterns over very long text, need changing. `scripts/API.md` lists the rules.
- The release builds use pinned versions of every tool.

The whole list, finding by finding, is in [PROGRESS.md](https://github.com/OttoApocalypse69/ACMS-MK3/blob/main/PROGRESS.md).
